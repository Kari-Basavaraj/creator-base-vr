# Implementation lessons / experience v3

- A named doorway is not proof of passage. Check approach, threshold and inside positions against both solid geometry and the walkable polygon.
- A seat count is not an occupied-capacity or accessibility certification. Show the proposed arrangement and keep validation limits explicit.
- Inspect fixed columns before placing stages and routes. Sample the complete route, including corners and transition zones.
- Mount kinetic pins beyond the finished wall face. A correct instance count can still hide a field inside a partition; verify a rendered re-import.
- Check important features from the entry/default camera, not only close-ups. Keep a dedicated exported-file viewer.
- Export a deliberate visual showcase and restore the browser state in `finally`; do not erase the visitor's shortlist or history.
- Keep hypothetical product and visitor data labelled as such. Browser-local history is not a shared community backend, and a rehearsal timer is not media capture.
- In a constrained browser-test runner, derive the test URL inside the browser rather than assuming Node process globals.
- Keep the static website portable: relative local modules, embedded GLB images, pinned vendor code and dependency-free structural checks.
